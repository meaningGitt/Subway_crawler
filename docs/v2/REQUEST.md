# 작업: 앉을 지도 seat-data 수집·가공 파이프라인 개선 (seat-evidence-v1 → v2)

## 배경
앉을 지도는 "몇 시 열차면 어디서부터 앉는지"를 타기 전에 알려주는 지하철 착석 안내 서비스다.
MVP 예측은 공공데이터로 만든 사전값에 사용자 착석 기록을 가중 보정하는 방식이다.
- 보정 비중: 기록 비중 = n ÷ (n + 10)
- 계산 주기: 하루 1회 배치
- 출력: "앉기 시작하는 역", "서서 가는 시간"

현재 스냅샷은 두 개다.
- analysis_csv_2026-11-08: 원본 8종
- coverage_expansion_2026-11-09: 서울시 OA-12252, OA-22441 추가

분석해 보니 아래 문제가 확인됐다. 원칙은 유지한다.
- 원본 보존 (SHA-256, manifest)
- 퍼지 매칭 금지
- 좌석 확률 생성 금지
- 4호선 칸 데이터를 다른 노선에 쓰지 않기
- 상충값 자동 덮어쓰기 금지

기존 회귀 테스트 28개는 계속 통과해야 한다.

## P0-1. 시간표(route_features / timetable_stops) 중복 버전 제거
현상:
- 1·3·4호선에 기준일이 다른 두 벌이 함께 들어 있다.
  - reference_date 2025-12-31: HH:MM 형식
  - reference_date 2026-05-31: HH:MM:SS 형식, train_no 앞에 S/K
- 그래서 같은 운행이 두 번 집계된다. 예: 4호선 평일 혜화 정차가 2025-12-31판 474회, 2026-05-31판 474회 = 총 948회.
- 4호선은 같은 운행이 '당고개'와 '불암산' 두 이름으로 섞여 있다.
- 1호선 2025-12-31판은 다음 역 도착 시각이 출발 시각보다 빠른 행이 18%다.
- 1호선 라인에 대경선(동대구·경산·구미)이 섞여 있다.
- 7호선 2022-04-30판, 우이신설선 2022-05-30판이 남아 있다.
- effective_date가 100% 결측이다.
- quality_valid=false가 149,516행(27%)이다. 원인은 역 키 결측 35%, 소요시간 결측 52%.

해야 할 것:
1. 노선별로 canonical 시간표 한 벌만 선택한다.
   - 선택 규칙을 config에 명시한다. 예: 운영기관 원본 우선, 같으면 최신 reference_date.
   - 나머지 버전은 원본에 보존하고 분석용 데이터셋에서 제외한다.
   - 제외 사유는 superseded_by_version으로 남긴다.
2. 시각을 HH:MM:SS로 통일한다.
   - 자정 넘김 운행은 24:xx:xx로 연속 표기한다.
   - 기존 "큰 자정 역전만 익일 처리" 규칙을 유지한다.
3. 역명 별칭을 명시적 alias 테이블로 처리한다. 예: 당고개 → 불암산(409).
   - 근거 출처(KRIC 라벨 등)를 남긴다.
4. 수도권이 아닌 노선(대경선 등)은 line 매핑에서 제외한다.
5. 기준일이 1년 이상 지난 버전은 stale=true로 표시한다.
6. 운행 단위 파생 컬럼을 추가한다.
   - is_origin_stop: 해당 정차역이 이 운행의 시발역인지
   - is_short_turn: 정규 종착이 아닌 중간 회차 운행인지
   - minutes_from_origin: 시발역부터 경과 분
7. 시행일 원본 필드나 게시일을 찾을 수 있으면 effective_date를 채운다. 못 찾으면 effective_date_source='unknown'.

완료 기준 (테스트로 추가):
- 같은 (line, day_type, station_key, departure_time, direction) 조합이 두 개 이상 버전에서 나오지 않는다.
- 4호선 평일 혜화 정차 수가 약 474이고, 948이 나오지 않는다.
- 1호선 canonical판에서 도착 < 출발 비율이 1% 미만이다.
- 2호선 평일 07~09시 신도림→대림 출발 운행이 42대, 그중 신도림 시발이 12대로 재현된다. 중복 제거 후에도 같아야 한다.

## P0-5. 구간 혼잡도 방향 정규화 + 혼잡도 감소 파생
배경:
- 개찰구 하차는 환승 하차를 못 잡는다.
- 평일 8시 기준, 구간 혼잡도 감소량과 개찰구 순하차(하차−승차)의 순위상관은 일반역 0.72, 환승역 0.37이다.
- 예: 8호선 잠실은 혼잡도 감소 1위인데 개찰구 순위는 34위다.
- 그래서 사전값의 1순위 근거를 구간 혼잡도 감소로 바꾼다.

방향 규칙 (데이터에서 확인함, 종착역 0% 위치와 출근 혼잡 방향으로 검증):
- 1·3~8호선: 상선 = 역코드 감소 방향, 하선 = 증가 방향
- 2호선 본선(201~243): 외선 = 역코드 감소, 내선 = 증가 (순환이라 243↔201 연결)
- 지선(까치산·신설동)은 별도 처리
- 역의 혼잡도 = 그 역을 출발해 다음 역으로 가는 구간의 혼잡도로 해석

해야 할 것:
1. 방향 규칙을 config로 정의한다.
   - 노선별로 종착역 0% 위치와 자동 대조하는 검증 테스트를 추가한다.
2. 새 데이터셋 segment_drop_features를 만든다.
   - 키: line, station_key, direction, day_type, time_bin
   - 컬럼: prev_station_key, congestion_pct, prev_congestion_pct, congestion_drop_pct, below_seat_line(congestion_pct ≤ 33.75)
   - 33.75 = 54석 ÷ 정원 160명. 비율 상수와 출처 메모를 config에 둔다.
3. time_bin을 '07:30' 형식으로 정규화한다. 지금은 '7시30분'이라 문자열 정렬이 깨진다.
4. 이 값은 '평균 혼잡도 기준 추정'이다. 좌석 확률이나 착석 보장으로 표현하지 않는다.

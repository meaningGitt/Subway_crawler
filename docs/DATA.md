매 회 metadata를 먼저 조회합니다. 수정일·제목·URL이 같으면 기존 원본으로 품질 검사합니다. 서버가 ETag/Last-Modified를 제공하면 조건부 요청을 사용합니다. 메타데이터를 갱신하지 않는 원본 수정도 발견하기 위해 7일마다 재검증합니다. 서버가 조건부 요청을 지원하지 않으면 이때 전체 다운로드가 필요합니다. `--force`는 즉시 재검증합니다. 다운로드 횟수나 세션 ID를 버전 키로 사용하지 않습니다.

출처당 직렬 요청 간격 최소 2초, 네트워크 및 429/5xx 최대 3회 시도, Retry-After 존중(120초 초과이면 다음 실행으로 넘김), connect/read timeout 15/90초, 응답 최대 32 MiB입니다. 인증·로그인·CAPTCHA를 우회하지 않습니다. 현재 출처는 키가 필요 없습니다. 키가 필요한 어댑터를 추가할 때 GitHub Secrets/환경변수만 사용하고 원본의 개인정보 포함 여부를 검토합니다.

## 식별과 누적

- 역사: `(출처, 공식 노선번호, 표준화한 서비스 노선명, 역번호)`. 경의중앙선과 경춘선이 같은 노선번호·역번호를 공유하는 원본 사례 때문에 서비스 노선을 포함합니다.
- 노선: `(출처, 노선번호, 원본 노선명)`. 수인선·분당선에 동일 코드가 사용되는 실제 원본을 구분합니다.
- 코드 목록: `(출처, 운영기관 코드, 노선 코드, 역 코드)`.
- 코드 및 서비스 명칭 자체가 변경되면 새 식별자로 누적합니다. 과거 식별자는 삭제하지 않으며 자동으로 물리적 역사 동일성을 추정하지 않습니다.
- 동일 식별자·동일 내용은 중복 저장하지 않습니다. 변경 시 최신 값과 history 버전을 함께 트랜잭션으로 갱신합니다. A→B→A도 3개의 버전으로 보존합니다.
- 한 원본의 중복 식별자는 기준일 최신 행을 선택하고 중복률을 기록합니다. 같은 기준일에 값이 충돌하면 해당 출처 승격을 중단합니다. 제외된 행도 원본 파일에는 보존됩니다.
- `reference_at`은 원본 기준일, `first_collected_at`/`last_collected_at`은 수집 확인 시각입니다. 코드 목록의 행별 기준일은 NULL입니다. 출처의 실제 다운로드 시각은 source_state의 last_downloaded에 저장합니다.
- 원본에서 사라진 행은 누적 DB에서 삭제하지 않습니다. 따라서 누적 노선별 건수는 현재 영업 역 수가 아닙니다.

## 품질

필수 열 삭제/중복, 식별자 충돌, 빈 데이터, 이전 누적 건수 대비 30% 이상 급감은 출처 실패입니다. 정상 출처는 계속 처리합니다. 실패한 새 원본은 진단용으로 남기고 이전 정상 state/records는 보존합니다.

좌표 범위, 날짜 파싱, 결측률, 중복률, 열 추가/변경, 새 데이터 여부, 출처 수정일, 노선별 확보 현황을 매 실행 계산합니다. 원본의 결측 좌표는 행을 지우거나 임의 보간하지 않고 `issues`에 기록합니다. 기준 24개 서비스 노선 존재 여부를 검사하며, 신설 노선·기관은 config와 매핑을 검토할 수 있도록 미매핑 노선을 보고합니다. 전체 역의 완전성은 별도 최신 운영기관 기준목록 대조가 필요하므로 `full_station_completeness_verified=false`를 유지합니다.

## PostgreSQL 확장 설계

기본 실행은 SQLite 단일 작성자입니다. 현재 PostgreSQL 어댑터를 구현했다고 주장하지 않습니다. 증대 시 Store 인터페이스(state/save_state/count/merge/raw/export)를 PostgreSQL 구현으로 교체하고 records/history의 복합 유일키와 출처별 트랜잭션을 그대로 유지합니다. payload는 JSONB, 시각은 timestamptz, 실행 잠금은 pg_try_advisory_lock, raw는 콘텐츠 주소 S3 호환 저장소로 옮깁니다. CSV/DB backup으로 이관하고 원본·history 건수/해시 검증 후 전환합니다. 코드/비밀키는 데이터 브랜치에 저장하지 않습니다.

# 통합 구현 및 검증 기록

빈 저장소의 최초 구현으로 다음 단계들을 하나의 실행 흐름에 연결했습니다.

1. 출처 등록·범위·갱신/이용 조건: config/sources.json, source.py.
2. HTTP 접근 확인·변경 탐지·제한 재시도·원본 수집: source.py, pipeline.collect.
3. 정제·표준화·복합 식별자·SQLite 누적/변경 이력·CSV: source.py, store.py.
4. 출처 독립 처리·품질 검사·원본 보존·보고서·실패 재실행: pipeline.py, CLI.
5. KST 09:00/22:00 예약·잠금·영구 누적·운영 설치: collect.yml, deploy/, OPERATIONS.md.

## 로컬 검증 (2026-11-07 KST)

- 공식 원본 실제 HTTP 수집: 역사 795, 한국철도공사 노선 11, 최신 수도권 역 코드 806건.
- 기준 서비스 노선 24개 존재 확인, GTX-A 코드 목록 9건 포함. 전체 실제 역의 완전성은 별도 검증 필요.
- 역사 원본 이상값 13행은 이슈 표시 후 보존. 좌표/기준일 등을 임의 생성하지 않음.
- 단위/통합 테스트: 멱등성·변경/되돌림 이력·다운로드 생략·동일 기준일 충돌·원본 급변/스키마 실패 보호·트랜잭션 롤백·수도권 범위·결측/범위 검사·flock 중복 생략·출처 실패 독립 및 선택 재시도·대기 실행 생략·메타데이터 안정성·CSV·GTX 코드/최신 게시 탐색·429 Retry-After.
- 실제 GitHub 등록/수동 실행 결과는 PR 및 Actions 실행 링크로 확인. 예약 시각 도래에 의한 schedule 이벤트는 수동 dispatch로 대신 검증했다고 주장하지 않음.
- macOS launchd / Linux systemd / cron은 설정·설치 방법을 제공하며 실제 등록은 하지 않음(GitHub를 운영 환경으로 선택).

## 한계

- GitHub 일정 지연/드롭/비활성화 정책 때문에 벽시계 정각 또는 영구 무인 가동을 보장할 수 없음.
- 등록한 공식 공개 데이터 상품을 수집하며, 실시간 열차 위치·모든 운영기관 시간표·모든 편의시설 API까지 구현된 것은 아님.
- PostgreSQL은 이관 가능한 인터페이스/스키마 설계이며 실행 구현은 SQLite.
- 원본 누락·오류·기관의 코드 변경은 자동 수집으로 해결할 수 없으며 품질 보고서에 드러내고 원본을 보존.
